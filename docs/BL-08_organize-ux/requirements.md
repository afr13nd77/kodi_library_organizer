# BL-08 — UX: улучшение флоу organize

## 1.1 Обзор

- **Что**: Переработка UI-флоу операции «Organize» — экран подтверждения путей перед сканированием и замена обязательного textviewer-превью на yesno с опциональным просмотром списка.
- **Кто**: Пользователь Kodi-аддона Library Organizer.
- **Зачем**: Текущий флоу неинтуитивен — textviewer закрывается только через Escape/Back (неочевидно), а пути источника и назначения выбираются порознь без общего обзора.

## 1.2 User Stories

```
US-01: Как пользователь, я хочу видеть оба пути (источник + назначение) и режим на одном экране перед сканированием,
       чтобы убедиться в корректности настроек без перехода в Settings.

US-02: Как пользователь, я хочу подтвердить операцию одной кнопкой "Да" с кратким саммари (N фильмов, режим),
       чтобы не разбираться с выходом из textviewer через Escape.

US-03: Как пользователь, я хочу иметь возможность посмотреть полный список операций перед подтверждением,
       но только по желанию — не обязательный шаг.
```

## 1.3 User Flows

```
FLOW-01: Organize — основной путь (happy path)

1. Пользователь выбирает "Organize library" в главном меню
2. Система читает настройки (source_dir, destination_dir, mode, ...)
3. Система показывает экран подтверждения путей:
   ┌──────────────────────────────────────────┐
   │         Library Organizer                 │
   │                                           │
   │  Источник:    D:\Movies                   │
   │  Назначение:  D:\Movies_Sorted            │
   │  Режим:       Перемещение                 │
   │                                           │
   │  Продолжить?                              │
   │                                           │
   │  [Да]    [Изменить]    [Отмена]           │
   └──────────────────────────────────────────┘
   → "Да" (yeslabel): переход к шагу 4
   → "Изменить" (customlabel): открыть addon Settings → после закрытия вернуться к шагу 2 (перечитать настройки)
   → "Отмена" (nolabel) / Escape: выход
4. Система валидирует пути → если ошибка → dialog.ok с текстом ошибки → возврат к шагу 3
5. Система сканирует директорию (с прогресс-индикатором если возможно)
6. Система показывает yesno с саммари + опция превью:
   ┌──────────────────────────────────────────┐
   │         Library Organizer                 │
   │                                           │
   │  Найдено фильмов: 42                     │
   │  Файлов к переносу: 128                  │
   │  Режим: Перемещение                       │
   │                                           │
   │  Начать?                                  │
   │                                           │
   │  [Да]    [Список]    [Отмена]             │
   └──────────────────────────────────────────┘
   → "Да" (yeslabel): переход к шагу 7 (выполнение)
   → "Список" (customlabel): открыть textviewer с полным списком → после закрытия вернуться к шагу 6
   → "Отмена" (nolabel) / Escape: выход
7. (только если НЕ dry_run) Выполнение операции
   Если dry_run — после шага 6 показать textviewer с превью и завершить.

FLOW-02: Пути не настроены

1-2. Как в FLOW-01
3. Один или оба пути пустые → вместо экрана подтверждения → browseSingle для недостающих путей → затем экран подтверждения
   → Если пользователь отменяет browse → выход

FLOW-03: Пользователь хочет изменить настройки

1-3. Как в FLOW-01
3a. Пользователь нажимает "Изменить" → открывается addon Settings
3b. После закрытия Settings → система перечитывает ВСЕ настройки → показывает экран подтверждения заново с обновлёнными значениями
```

## 1.4 Acceptance Criteria

```
AC-01 (US-01):
  GIVEN: настроены source_directory и destination_directory
  WHEN: пользователь выбирает "Organize library"
  THEN: появляется yesnocustom-диалог с текстом, содержащим оба пути и режим (Move/Copy)
        AND кнопки: "Да", "Изменить", "Отмена"
        AND нажатие "Изменить" открывает Settings и после возврата диалог показывается заново с обновлёнными значениями

AC-02 (US-01):
  GIVEN: source_directory пуст
  WHEN: пользователь выбирает "Organize library"
  THEN: открывается browseSingle для выбора source
        AND после выбора показывается экран подтверждения путей

AC-03 (US-02):
  GIVEN: сканирование нашло N групп фильмов
  WHEN: показывается экран подтверждения операции
  THEN: в диалоге yesnocustom отображается количество фильмов, количество файлов, режим
        AND кнопки: "Да", "Список", "Отмена"
        AND нажатие "Да" запускает выполнение (или показывает превью в dry_run)

AC-04 (US-03):
  GIVEN: пользователь на экране подтверждения операции
  WHEN: нажимает "Список"
  THEN: открывается textviewer с полным списком операций
        AND после закрытия textviewer возвращается на экран подтверждения (yesnocustom)

AC-05 (US-02):
  GIVEN: dry_run включён
  WHEN: пользователь нажимает "Да" на экране подтверждения операции
  THEN: показывается textviewer с полным превью
        AND после закрытия — завершение без выполнения
```

## 1.5 Вне скоупа

- Кастомные WindowXMLDialog (зависимость от скинов)
- Изменение флоу Undo
- Изменение логики сканирования или организации
- Новые настройки в settings.xml
- Изменения в shared-модулях (scanner, organizer, name_parser)

## 1.6 Зависимости

- Kodi Python API: `xbmcgui.Dialog().yesnocustom()` — доступен с Kodi v19 (Matrix)
- Все изменения в одном файле: `script.library.organizer/python/main.py`
- Локализация: новые строки в strings.po (en_GB + ru_RU)
